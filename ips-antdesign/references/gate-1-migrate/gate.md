# Gate 1: Complete, Faithful Adoption

What was this output created to accomplish, and could a downstream user or developer still miss that goal because the migration is partial, loses meaning, or permits another UI system to grow back?

Run after full-scope verification. Prefer one independent reviewer when the host permits delegation, because this is an architecture change and future development contract. Otherwise perform an explicit independent-stance self-review and disclose that review mode.

Supply the original request/scope, immutable baseline identity, derived inventory/mapping, version/theme choices, final diff, actual guard/test/browser evidence and named exceptions. The reviewer must inspect evidence, not accept the producer's summary as proof.

## Blocking Invariants

- All in-scope surfaces/states/information/actions are represented and usable, including mobile; exclusions are approved and disclosed.
- Ant components and token authority govern the real implementation; old runtime UI and duplicate primitive/style systems are gone.
- Protected framework, SSR, auth, data semantics and AI behavior remain intact; required checks actually pass against the final tree.
- Future development has working repo-owned guards and an agent entry pointing to the adopted workflow, not only a one-time report.

Record `PASS` or `INCOMPLETE`, concrete evidence and findings. One targeted repair/recheck for substantive defects; if the cause is missing authority/evidence, return to that prerequisite instead of polishing. Do not reopen a pass for stylistic preferences.

A goal invocation must produce the same final state and evidence. A successful host goal, CLI call or screenshot is never this gate's verdict.
